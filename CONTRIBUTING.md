## Code of conduct

This project follows the [Contributor Covenant](CODE_OF_CONDUCT.md). By participating you are
expected to uphold it. Report unacceptable behaviour to the maintainers through a private
security/report channel (see [SECURITY.md](SECURITY.md)).

## Getting the project running

Requirements:

| Requirement | Why |
| --- | --- |
| Node.js **>= 22.6** | uses the built-in `node:sqlite` and native TypeScript type-stripping |
| `ffmpeg` / `ffprobe` on `PATH` | transcoding, pitch shifting and mixing |
| `openssl` on `PATH` (optional) | signs the self-signed certificate for the mobile HTTPS entry |
| Chromium-based desktop browser | `AudioWorklet` + `MediaElementSource` |

```bash
npm install
./openktv.sh start          # foreground, Ctrl+C to stop
# then open http://127.0.0.1:8787
```

Useful commands:

```bash
npm run dev           # dev mode (Vite HMR + backend --watch), foreground
npm run build         # production front-end bundle
npm start             # production server, foreground
npm run typecheck     # tsc over both tsconfigs (web + server)
npm test              # unit tests (no network, no real Chrome needed)
npm run test:e2e      # browser end-to-end (needs a real Chrome)
npm run check:i18n    # locale catalog consistency + key-usage checks
npm run check:license # SPDX licence headers on every source file
npm run smoke:i18n    # headless-Chrome smoke test of the language switcher
```

> **About `.npmrc`**: the repository pins the npm cache to `./.npm-cache` (git-ignored) so that
> `npm install` keeps working on machines whose `~/.npm` contains root-owned leftovers. If your
> global cache is healthy, delete `.npmrc` to go back to the default behaviour.

## Where things live

```
server/src/      Express API, SQLite metadata, ffmpeg orchestration, job queue
web/src/         React app (desktop pages + /m mobile pages)
shared/          Types and pure helpers used by both sides
scripts/         dev server, backup, e2e browser driver, i18n checker
tests/           node:test suites (unit + integration against real ffmpeg)
```

The project intentionally has **no runtime dependencies beyond the seven in `package.json`**.
i18n, theming, toasts, confirmations and the QR menu are all implemented in-tree with zero
dependencies. Please keep it that way unless there is a compelling reason.

## Before you open a pull request

1. `npm run typecheck` passes.
2. `npm test` passes.
3. `npm run check:i18n` passes (only relevant if you touched UI text).
4. `npm run check:license` and `npm run smoke:i18n` pass.
4. `npm run build` succeeds.
5. No new runtime dependencies without discussing it in an issue first.

Small, focused pull requests are reviewed much faster than large ones. If a change is big,
open an issue first and describe the plan.

## Commit messages

The history uses a single-line Chinese convention:

```
<类型>：<做了什么> —— <为什么 / 细节>
```

`类型` is one of `功能` (feature), `改进` (improvement), `修复` (fix), `文档` (docs),
`运维` (ops), `测试` (tests). Keep the subject under ~70 characters and explain the *why* in
the body when it is not obvious.

## Internationalisation (i18n)

**No user-facing string may be hard-coded in a component.** Everything goes through the
catalogue.

```tsx
import { useI18n } from '../i18n';

export function Example() {
  const { t, locale } = useI18n();
  return <button title={t('common.cancel')}>{t('common.save')}</button>;
}
```

Rules the codebase follows:

- **Catalogues live in `web/src/i18n/locales/<locale>/<area>.ts`.** One file per feature area
  (`common`, `library`, `discover`, `works`, `sing`, `detail`, `retake`, `mobile`,
  `components`, `audio`, `errors`). Never edit `locales/index.ts` by hand — it is generated by
  the merge and validated by `npm run check:i18n`.
- **Keys are stable, semantic, dotted and snake-cased** (`library.upload`, `error.track_not_found`).
  Never rename a key without updating every locale; never key off the source text.
- **Interpolation uses `{name}` placeholders**, and the *same* placeholder set must exist in
  every locale (`npm run check:i18n` enforces this).
- **Plurals** go through `plural('key', count)`, which resolves `key.zero|one|two|few|many|other`
  through `Intl.PluralRules`.
- **Formatting** never uses manual concatenation. Use the helpers on the i18n context:
  `fmt.number`, `fmt.percent`, `fmt.bytes`, `fmt.duration`, `fmt.dateTime`, `fmt.list`.
- **Language tags are BCP-47** (`zh-CN`, `en`). The active locale is persisted in
  `localStorage`, can be forced with `?lang=`, and is always mirrored onto
  `<html lang>` so screen readers and search engines see the right language.
- **Server responses stay language-neutral.** Endpoints return a machine-readable `code` plus
  `params`; the client turns them into sentences in the user's locale
  (see `web/src/i18n/locales/*/errors.ts`).

## Adding a new locale

1. Create `web/src/i18n/locales/<BCP-47 tag>/` with one file per area, copying
   `zh-CN` as the reference.
2. Register the tag in `web/src/i18n/locales/index.ts` (`LOCALES` + `LOCALE_LABELS`).
3. Run `npm run check:i18n` — it reports missing keys, extra keys and placeholder mismatches.
4. Add the language to the switcher (it picks labels up automatically) and to the table in
   [docs/i18n.md](docs/i18n.md).

`zh-CN` is the reference catalogue: it must always contain every key.

## Reporting bugs

Use the bug-report template and include the platform, browser, Node/ffmpeg versions, and the
steps to reproduce. Security issues must **not** be filed as public issues — see
[SECURITY.md](SECURITY.md).

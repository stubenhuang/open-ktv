# Open KTV

简易版全民K歌（Web）：**点歌或上传伴奏 → 跟唱歌词 → 戴耳机带耳返演唱 → 服务端合成 192kbps MP3 → 试听 / 调整效果与音效 / 下载**。

单机自用，无需登录。伴奏库上传**只收音频**（弹窗里选音频 + 可选 .lrc 歌词）；点歌台**内置 5sing 伴奏搜索/下载**（默认开箱即用），也可以再配自建曲库源。

## 功能

| 模块 | 说明 |
|---|---|
| 伴奏库 | 上传弹窗（音频必填 + 歌词可选，可一次多选音频）、列表试听、编辑弹窗（歌名/歌手/歌词/对轴）、删除；单文件上限 1GB；**只支持音频格式**；删除伴奏不再被作品拦截（作品保留，但不能再混音） |
| 点歌台 | 内置 5sing 伴奏源（默认开启）：输入歌名/歌手 → 点「搜索」（不边打字边搜）→ 点歌（服务端自动下载入库）→ 去演唱；点歌时自动从酷狗匹配 LRC；重复点歌自动去重；也可叠加自建曲库源 |
| 歌词跟唱 | 支持 LRC（`[mm:ss.xx]`/多时间戳/`[offset:]`）；演唱页逐行滚动高亮、点行跳转、整曲对轴微调（±30s）、**逐字填充**（卡拉 OK 式）、**下一句次大显示** |
| 格式兼容 | 浏览器能直接播的原文件直接用；ape / wma / ogg / h265 音频等**自动转码**成 mp3 代理（伴奏库不再接受视频格式） |
| 演唱页 | 麦克风设备下拉（**只列外置输入**，内置麦克风默认隐藏）、实时音量条、伴奏音量 / 耳返音量两个滑块、人声耳返一键静音、MV 画面播放（仅点歌来源的视频伴奏；上传只收音频） |
| 录音 | 只录麦克风**干声**（WAV，采样点精确），伴奏不进录音文件 |
| 自动对齐 | 先起录 0.15 秒静音再放伴奏，用音频图上的起播探测器在渲染时钟精确测量伴奏真正起播的时刻，混音时人声提前这段间隔（偏移可为负） |
| 混音 | 人声音量 / 伴奏音量 / 八档混响 / 人声对齐微调；「实时试听」改动立即生效，点「合成」出 MP3 |
| 音效 / 修音 | 十档预设（自然/温暖/明亮/甜美/磁性/空灵/轻柔/有力/复古/现场）、三段均衡、压缩量、去齿音、降噪 |
| 响度 | 干声与伴奏分别自动响度归一化，末端限幅防削波 |
| 作品库 | 列表、播放、下载 MP3、改名、删除；合成后自动定位到对应作品 |

## 环境要求

- **Node.js ≥ 22.6**（用到内置 `node:sqlite` 和原生 TypeScript 类型擦除；开发时用的是 24.2）
- **ffmpeg / ffprobe 在 PATH 里**（`ffmpeg -version` 能跑就行）
- **桌面 Chrome / Edge**（音频部分用了 AudioWorklet、MediaElementSource，只保证 Chromium 系）
- **一副有线耳机** —— 耳返和「不串音」都靠它

## 快速开始

```bash
npm install
./openktv.sh start
```

然后打开 <http://127.0.0.1:8787>。它会在当前终端前台跑、日志实时打出来，按 `Ctrl+C` 就关掉。

### 服务管理脚本 `openktv.sh`

推荐用它来开关服务：默认**占住当前终端前台跑**（日志实时打出来，`Ctrl+C` 关闭），
加 `--daemon` 才是放到后台。两种方式都会自动记 pid、写日志、检查端口。

```bash
./openktv.sh start            # 启动（生产模式：单进程，会先自动构建前端）——前台跑，Ctrl+C 关
./openktv.sh start --dev      # 启动开发模式（Vite 热更新 + 后端 --watch，改代码自动生效）
./openktv.sh start --daemon   # 放后台跑（不占终端），启动完就返回，用 stop 关
./openktv.sh stop             # 关闭
./openktv.sh stop --force     # 关闭，并清掉占着端口的残留进程
./openktv.sh restart          # 重启（沿用上次的模式，同样是前台跑）
./openktv.sh status           # 查看状态（运行中退出码 0，没运行退出码 1）
./openktv.sh logs             # 跟踪日志（Ctrl+C 退出，不会关掉服务）
```

前台模式下 `Ctrl+C` 一次是优雅关闭（先给服务发信号，最多等 10 秒收尾），再按一次就是强制结束。
不管前台后台，pid 都写在同一个 `.run/openktv.pid` 里，所以另开一个终端跑 `status` / `stop` 一样管用 ——
在别的终端 `stop` 掉之后，前台那个脚本会自己收尾退出。

| 模式 | 进程数 | 访问地址 | 说明 |
|---|---|---|---|
| `start`（默认，生产） | 1 | <http://127.0.0.1:8787> | 单进程同时托管前端和 API。每次启动都会重新构建前端（约 0.1 秒） |
| `start --dev` | 3 | <http://127.0.0.1:5173> | Vite HMR + 后端 `--watch`，改代码立刻生效 |

`--daemon` 只决定「占不占终端」，跟上面两种模式是正交的。

相关文件（都在 `.run/`，已 gitignore）：`.run/openktv.pid`（进程号）、`.run/openktv.mode`
（上次用的模式，`restart` 会沿用它）、`.run/openktv.log`（完整日志）。

**换端口**：`PORT` 是后端，`WEB_PORT` 是开发模式下的前端，两个会一起生效
（`vite.config.ts` 的代理目标跟着 `PORT` 走）：

```bash
PORT=9000 WEB_PORT=5273 ./openktv.sh start --dev
```

### 不想用脚本的话

```bash
npm run dev                   # 开发模式，前台跑，Ctrl+C 关
npm run build && npm start    # 生产模式，前台跑，Ctrl+C 关
```

前台跑的时候 `Ctrl+C` 一次就能把前后的进程都收干净（`dev.mjs` 做了信号转发）；
`./openktv.sh start` 默认就是这套行为，只是多了构建前端、查端口、记 pid 和日志。

### 如果 `npm install` 报 EPERM

机器上 `~/.npm` 里有 root 属主的文件时 npm 写缓存会被拒。项目已经带了 `.npmrc`
把缓存改到项目内的 `./.npm-cache`，正常情况下不用管。想彻底修好：

```bash
sudo chown -R $(id -u):$(id -g) ~/.npm   # 修好后可删掉 .npmrc 里那一行
```

## 使用流程

1. **准备伴奏**：两条路都行 ——
   - **点歌台**：内置的 5sing 伴奏源默认就能搜，输入歌名/歌手 → 点「搜索」（打字不会自动触发，
     免得每个字符都打一次接口）→ 点「点歌」，服务端把伴奏下载入库（会自动尝试匹配 LRC 歌词），
     完成后点「去演唱」。
   - **伴奏库**：点上传区（或把文件拖进去）会弹出上传弹窗 —— 选一个音频文件（必填，可多选），
     想跟唱再带上 `.lrc` 歌词（可选），点「开始上传」，等状态从「转码中」变成可用。
     **只收音频**：mp4 / mkv / avi 这类视频会被挡下（弹窗里提示，服务端也会再拦一次）。
2. **加歌词**（可选）：点歌入库时会自动从酷狗匹配 LRC；伴奏库里也可以点「编辑」打开编辑弹窗 ——
   「自动获取歌词」补一份，或粘贴 LRC 文本 / 选一个 `.lrc` 文件。
   每行都要有时间戳（`[00:12.00]`），纯文本歌词会被拒 —— 没有时间轴就没法跟唱。
3. **去演唱**：戴上耳机，选好麦克风（对着说话看音量条有没有反应）。
   设备下拉**只列外置输入**：MacBook 机身内置麦克风默认不出现，没插外置麦克风时下拉是空的、
   「开始演唱」保持禁用，不会偷偷回退到内置麦克风；下拉下面那行会写明**隐藏了哪些设备**，
   临时想用内置的点「显示全部设备」即可。有歌词的话舞台区会显示逐行高亮的跟唱歌词，点某一行可以跳过去。
4. **开始演唱**：伴奏/画面开始播放，耳机里同时听到伴奏和自己的声音。
   同时进入**全屏歌词页**：歌词铺满整个视口（视频伴奏铺满画面并压暗做底，音频伴奏是深色底大字），
   当前行**逐字点亮**、**下一句次大显示**，长句自动缩字号；左上角是歌名和「录音中 + 计时」，
   **右上角是「完成录制」和「取消录制」** —— 录音期间只有这一处操作入口。
   伴奏音量/耳返音量全屏里调不了，唱之前在那两个滑块上调好。
5. **完成录制**：点右上角「完成录制」（或者伴奏放完自动结束）。点下去按钮立刻变成「正在合成…」并禁用，
   防重复提交；干声上传后服务端合成 MP3，几秒后跳转到作品编辑页。
   唱砸了就点「取消录制」—— 丢掉这条干声，原路回到待唱状态，伴奏回到开头。
6. **调整效果 / 修音**（编辑页：**所有元素一屏放完，不需要滚动**；左边「音效」、右边「音量 / 修音 / 对齐 + 合成」）：
   点「实时试听」播放，然后调
   **十种人声预设**、**八种人声混响**（原声 / 小房间 / 金属板 / 大厅 / 演唱会 / 教堂 / 体育场 / 峡谷，按空间由小到大排）、
   人声音量/伴奏音量、三段均衡、压缩量、去齿音、降噪，
   以及「人声对齐微调」（滑块或直接输入毫秒数，范围 ±1000ms）—— 改动**立即**在试听里生效，不用等。
   预设只是「一组具名参数」：点一下把数值写进滑块，之后还能继续手调（手调过就不再高亮任何预设）。
   控件旁的小图标（`i` = 这是什么，`!` = 试听与成品不一样 / 容易误用）里收着这条参数的说明，
   鼠标移上去或者按 Tab 聚焦才展开 —— 页面上不留成段文字，一屏才放得下。
   满意后点「合成」：服务端用干声重新出一版 MP3，页面**直接返回作品库并定位到这首作品**，
   在列表里等「正在合成…」变成「已就绪」即可。

   > **伴奏删了之后**：作品和伴奏已经解耦 —— 删伴奏不再被「下面有作品」拦住，
   > 作品记录和成品 MP3 都留着（列表里标「伴奏已删除」），还能播放 / 下载，
   > 但实时试听和重新合成都需要伴奏文件，所以作品编辑页只剩改名和删除。
7. **播放 / 下载**：都在作品库列表页 —— ready 的作品直接内嵌播放，或点「下载 MP3」拿 192kbps 立体声文件。

> **实时试听里听不到的是降噪**：没有对应的 Web Audio 节点，只在「合成」后的成品里生效，页面上有明确提示。

## 曲库与歌词

「点歌台」有**两个内置源，默认开启、开箱即用**：

| 源 | 搜什么 | 点歌时发生什么 |
|---|---|---|
| **5sing 伴奏** | 关键词搜伴奏；空关键词列「热门伴奏」 | 服务端现取下载地址（主 CDN 失败自动换备用）→ 下载入库 |
| **酷狗歌词** | 点歌后按歌名/歌手自动匹配；也可在伴奏库编辑页手动「自动获取歌词」 | 搜歌拿 hash → 查歌词候选（带评分/时长）→ 下载 LRC 入库 |

- 5sing 的伴奏是用户上传的 mp3，**没有 MV**，质量与版权由上传者负责。
- 歌词是**附赠功能**：匹配不到、酷狗挂掉，都只导致「这首没歌词」，伴奏照常入库，
  之后还能在伴奏库编辑页手动「自动获取歌词」或上传 `.lrc`。

### 自建曲库源（可选）

想在 5sing 之外再挂自己的库，用 `LIBRARY_SOURCES` 配清单地址。源站**只需要托管一份静态
JSON**，不需要实现任何服务端逻辑 —— NAS、对象存储、局域网 HTTP、静态站点都能当源用，
也不需要鉴权：

```json
{
  "version": 1,
  "name": "我的伴奏库",
  "items": [
    {
      "id": "qingtian",
      "title": "晴天",
      "artist": "周杰伦",
      "durationSec": 269,
      "kind": "audio",
      "url": "qingtian.mp3",
      "lrc": "qingtian.lrc",
      "sizeBytes": 12345678
    }
  ]
}
```

- `id` 可省略，省略时用 `url` 兜底 —— 去重键必须在源内稳定唯一。
- `url` / `lrc` 相对或绝对都行（相对地址按清单地址解析）；只接受 `http(s)`。
- `lrc` 可选；有的话点歌时会把歌词一起入库，唱歌时直接能跟唱。
- 清单结果按 TTL 缓存在内存里，搜索是纯本地过滤；某个源挂了不影响其他源。

**关掉内置源**：`FIVESING_ENABLED=0` / `KUGOU_LYRICS_ENABLED=0`（见下面「配置」）。

## 数据存放

全部在项目下的 `data/`（已加进 `.gitignore`）：

```
data/
  ktv.db          SQLite 元数据
  originals/      原始伴奏（手动上传的副本 / 点歌下载的文件；转码后也保留，混音用的就是它）
  proxies/        转码出来的播放代理 mp4/mp3
  vocals/         每次演唱的干声 WAV（重新混音的依据，任何处理都不会改写它）
  works/          合成好的成品 MP3
  tmp/            临时文件，启动时会清空
```

**备份**直接拷整个 `data/` 就行。**重置**就把 `data/` 删掉再启动。

## 配置

都是环境变量（在 `./openktv.sh start` 前面带上即可）：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8787` | 后端端口（`openktv.sh` 和 `vite.config.ts` 的代理都会跟着走） |
| `WEB_PORT` | `5173` | 开发模式下 Vite 的端口 |
| `HOST` | `127.0.0.1` | 监听地址，单机自用默认只绑回环 |
| `FFMPEG_BIN` | `ffmpeg` | ffmpeg 路径（不在 PATH 里时用绝对路径） |
| `FFPROBE_BIN` | `ffprobe` | ffprobe 路径 |
| `LOG_LEVEL` | `info` | 日志详细程度：`debug` / `info` / `warn` / `error`（开发模式 `dev.mjs` 默认 `debug`） |
| `DATA_DIR` | `<项目>/data` | 数据目录整体位置，测试靠它指向临时目录 |
| `LIBRARY_SOURCES` | 空 | 自建曲库源列表，逗号分隔；每项是 `名字=清单URL` 或裸 URL（协议见上文）。内置 5sing 源默认就有，不用配 |
| `LIBRARY_CACHE_TTL_MS` | `600000` | 清单缓存时长；搜索是本地过滤，不需要每次敲字都打源站 |
| `LIBRARY_SEARCH_TIMEOUT_MS` | `5000` | 单个源的超时；超时即视为该源不可用，**不影响其他源** |
| `LIBRARY_DOWNLOAD_TIMEOUT_MS` | `900000` | 单个伴奏的下载超时（大 MV 可能几百 MB） |
| `FIVESING_ENABLED` | `1` | 内置 5sing 伴奏源开关；`0` 关掉 |
| `FIVESING_SEARCH_BASE` | `http://search.5sing.kugou.com` | 5sing 关键词搜索地址（可整体指到镜像） |
| `FIVESING_WEB_BASE` | `http://5sing.kugou.com` | 5sing 站点地址（空关键词的热门伴奏页） |
| `FIVESING_API_BASE` | `http://mobileapi.5sing.kugou.com` | 5sing 元数据 / 下载地址接口 |
| `KUGOU_LYRICS_ENABLED` | `1` | 酷狗歌词自动匹配开关；`0` 关掉 |
| `KUGOU_SONG_SEARCH_BASE` | `http://mobilecdn.kugou.com` | 酷狗搜歌接口（该域名只有 http） |
| `KUGOU_LYRICS_BASE` | `https://lyrics.kugou.com` | 酷狗歌词查询 / 下载接口 |
| `KUGOU_LYRICS_TIMEOUT_MS` | `8000` | 歌词三步的总预算；别让点歌任务卡在歌词上 |

自建源 + 关掉内置源的例子：

```bash
LIBRARY_SOURCES="我的伴奏库=https://nas.local/ktv/index.json" FIVESING_ENABLED=0 ./openktv.sh start
```

多个源用逗号分隔；名字可以省略（省略时用清单里的 `name`，再不行用主机名）。

## Design

Three decisions shape everything else:

1. **Zero runtime dependencies.** No `i18next`, no `react-intl`, no message-format compiler.
   The catalogue is a plain object, the runtime is a React context, and the checks are a Node
   script. That keeps `dependencies` at the seven packages it has always been, and keeps the
   bundle small.
2. **Keys are semantic and stable.** `library.upload`, not `上传伴奏`. The key identifies the
   *slot*, not the current wording — so copy can be rewritten without touching code, and a
   translation memory stays valid.
3. **The server does not speak.** Endpoints return `{ code, params }`; sentences are assembled
   in the reader's language. Adding a UI language never requires a backend deploy.

## Where the strings live

```
web/src/i18n/
  types.ts             Locale / Messages / MessageVars
  catalog.ts           LOCALES, CATALOGS, MessageKey, lookup(), matchLocale()
  format.ts            Intl-backed formatters + interpolation + plurals
  I18nProvider.tsx     <I18nProvider>, useI18n(), translateWith()
  index.ts             the public API (what components import)
  locales/
    zh-CN/<area>.ts    reference catalogue — must contain every key
    en/<area>.ts       English
```

One file per feature area, so two people can translate at once without stepping on each other:

| area | covers |
| --- | --- |
| `app` | document title, language names, network/HTTP fallbacks |
| `nav` | navigation bar |
| `common` | cross-cutting verbs, states, field labels, units |
| `library` | backing-track library page |
| `discover` | song-discovery page |
| `sing` | singing page |
| `works` | works library |
| `detail` | work detail / effect editor |
| `retake` | segment re-take page |
| `mobile` | phone UI (`/m`) + mobile-entry reason codes |
| `components` | shared components (QR menu, dialogs, toasts, token gate) |
| `audio` | microphone / recording / mix vocabulary |
| `errors` | **server error codes** — see below |

`zh-CN` is the reference catalogue. Every other locale must contain exactly its key set.

## Using it in a component

```tsx
import { useI18n } from '../i18n';

export function LibraryPage() {
  const { t, fmt, plural, locale } = useI18n();
  return (
    <button title={t('library.uploadAria')} onClick={onUpload}>
      {t('library.upload')}
    </button>
  );
}
```

`t()` covers **every** user-facing string: JSX text, `title=`, `aria-label=`, `placeholder=`,
`alt=`, `confirm()` titles / messages / button labels, `toast()` messages, `alert` text, and
sentences built with template literals.

```tsx
// with interpolation
t('library.delete.confirm', { title: track.title })

// plurals
plural('library.trackCount', tracks.length)

// formatting
fmt.bytes(track.size)
fmt.duration(track.duration)
fmt.dateTime(track.createdAt)
```

`useI18n()` returns:

| member | what it is |
| --- | --- |
| `locale` | current BCP-47 tag (`zh-CN`, `en`) |
| `locales` | the supported tags |
| `localeLabels` | each language's name *in itself* (for the switcher) |
| `setLocale(next)` | switch language, persist, update `<html lang>` |
| `t(key, vars?)` | look up a message |
| `plural(key, count, vars?)` | look up a plural form |
| `fmt` | the Intl formatters |

## Outside React

`engine.ts`, `api.ts` and other plain modules cannot call a hook. They use the function twins:

```ts
import { translateWith, createFormatters } from '../i18n';
import { apiLocale } from '../api';

const message = translateWith(apiLocale(), 'audio.micPermissionDenied');
const label = createFormatters(apiLocale()).bytes(size);
```

`apiLocale()` is kept in sync by `I18nProvider` — see the `useEffect` in
`I18nProvider.tsx` that calls `setApiLocale`.

## Formatting

Never concatenate numbers, units or dates by hand. Use `fmt`:

| helper | example (`zh-CN` / `en`) |
| --- | --- |
| `fmt.number(1.5)` | `1.5` / `1.5` |
| `fmt.integer(1234)` | `1,234` / `1,234` |
| `fmt.percent(0.42)` | `42%` / `42%` |
| `fmt.signed(3)` | `+3` / `+3` |
| `fmt.bytes(1536)` | `1.5 kB` / `1.5 kB` |
| `fmt.duration(3725)` | `1:02:05` / `1:02:05` |
| `fmt.dateTime(ts)` | `2025/01/02 03:04` / `01/02/2025, 03:04` |
| `fmt.list(['a','b','c'])` | `a、b和c` / `a, b, and c` |

Two duration helpers are deliberately *not* locale-dependent, because they are numeric clocks
rather than sentences: `fmt.duration()` (`m:ss` / `h:mm:ss`) and `formatTimer()`
(`mm:ss.mmm`, recording timer).

`web/src/utils.ts` exposes the same formatters as free functions for non-React callers:
`formatBytes(bytes, locale)`, `formatDateTime(ts, locale)`, `formatRelativeTime(ts, now, locale)`.

## Plurals

`plural(key, count)` resolves `key.zero | key.one | key.two | key.few | key.many | key.other`
through `Intl.PluralRules`, falling back to the unsuffixed `key` when the language has no
dedicated form.

```ts
// zh-CN — Chinese has no singular/plural split, so .one repeats .other
'library.trackCount': '共 {count} 首',
'library.trackCount.one': '共 {count} 首',
'library.trackCount.other': '共 {count} 首',

// en
'library.trackCount': '{count} tracks',
'library.trackCount.one': '{count} track',
'library.trackCount.other': '{count} tracks',
```

The unsuffixed base form is required: `check:i18n` anchors key existence on it, and it is the
documented fallback.

## Language detection and persistence

Priority, highest first:

1. **`?lang=zh-CN` / `?lang=en`** — so a shared link can carry the language.
2. **`localStorage['ktv.locale']`** — the user's last choice.
3. **`navigator.languages`** — browser preference. Region variants match on the primary
   subtag (`en-GB` → `en`, `zh-TW` → `zh-CN`).
4. **`zh-CN`** — the reference language.

Switching language also:

- writes `<html lang>` (screen readers, search engines, browser translation buttons),
- rewrites `document.title`,
- pushes the locale into `api.ts` so server error codes re-render in the new language.

## Server-side errors

`shared/types.ts` defines `ApiErrorCode`, a flat list of stable snake_case identifiers.
Every error response is:

```json
{ "code": "track_not_found", "message": "Track does not exist" }
{ "code": "work_retake_segment_too_short", "message": "The re-take range is too short (at least 1.5 seconds)", "params": { "limit": 1.5 } }
```

`message` is an **English fallback for `curl` and scripts** — the browser never shows it when
a translation exists. `ApiError` (in `web/src/api.ts`) turns `code` + `params` into a sentence
in the reader's language at construction time, so components just read `error.message`.

To add an error code:

1. add it to `ApiErrorCode` in `shared/types.ts`;
2. add an English template to `ERROR_MESSAGES` in `server/src/httpError.ts`;
3. add `error.<code>` to **every** locale's `errors.ts`.

`npm run check:i18n` verifies all three agree, including that the `{placeholder}` sets match.

## Adding a locale

1. `cp -r web/src/i18n/locales/en web/src/i18n/locales/ja` and translate every value. Keep the
   keys and the `{placeholders}` byte-identical.
2. Register the tag in `web/src/i18n/catalog.ts`:
   - add it to `LOCALES`,
   - add a `CATALOGS` entry,
   - add it to `localeLabelsIn` and to the `localeLabels` map in `I18nProvider.tsx`.
3. Run `npm run check:i18n` and fix everything it reports.
4. Add the language to the table below. The switcher picks labels up automatically.

| locale | status | notes |
| --- | --- | --- |
| `zh-CN` | reference | Simplified Chinese; every key must exist here |
| `en` | complete | English |

## The checks

```bash
npm run check:i18n      # catalogue consistency
npm run check:license   # SPDX licence headers
npm run smoke:i18n      # browser-level smoke test of the language switcher
```

`smoke:i18n` builds the app, opens it in headless Chrome over CDP, and asserts that the first
screen renders in the reference language, that switching updates the navigation **and**
`<html lang>`, that the choice survives a reload (localStorage), and that `?lang=` overrides it.
It needs a Chrome/Chromium binary — set `CHROME_BIN` if the script cannot find one.

`check:i18n` fails on:

- a missing or extra key in any locale,
- a mismatch in the `{placeholder}` set between locales,
- an empty message,
- an `ApiErrorCode` without an `error.<code>` entry (or a placeholder mismatch against the
  server template),
- a `t()` / `plural()` / `translateWith()` key that does not exist in the catalogue.

Template-literal keys (`` t(`mobile.reason.${code}`) ``) are validated by static prefix: at
least one catalogue key must start with the prefix. The dynamic suffix is type-checked by
TypeScript through `NetworkReasonCode`.

Both checks run in CI on every push and pull request.

## Things that are deliberately not translated

Not every Chinese string in the repo is a bug:

- **Comments.** The codebase is commented in Chinese. Comments are for developers.
- **Operator logs.** `log.info` / `log.warn` / `log.error` output goes to `.run/openktv.log`
  and is read by whoever runs the server. It stays Chinese.
- **Internal invariant errors.** `throw new Error('engine not started')`-style programmer
  errors are never rendered; they may stay English.
- **`shared/` helpers used by the server log.** `describePitch()` / `describeReverb()` feed
  the mix log line in `server/src/routes/works.ts`, so they stay Chinese there. The UI does
  **not** use them directly — it goes through `audio.*` keys.
- **User data.** Song titles, artists, lyrics, file names and device labels come from the
  user or the OS. Never translate them; translate only the words *around* them.
